# Custom Music

**Слушай свою музыку в Minecraft** — положи аудиофайлы в папку, получи ванильные
пластинки с треками и играй их в проигрывателе (jukebox) для всех игроков вокруг.
А для полного контроля поставь новый блок **Juke Box**: ПКМ по нему открывает меню
с выбором трека, зацикливанием, громкостью и дальностью слышимости.

| | |
|---|---|
| Minecraft | 1.21.1 |
| NeoForge | 21.1.x (собрано против 21.1.77) |
| Java | 21 |
| Mod ID | `custommusic` |
| Версия | **1.1.1** |
| Лицензия | MIT (код) · кодеки: LGPL + public domain (см. ниже) |

Мод работает **в одиночной игре** и на **выделенном сервере** (мод нужен на обеих
сторонах: сервер сканирует/раздаёт, клиент играет).

## Что нового в 1.1.1

1.1.0 → 1.1.1 — исправление краша `/customdisc reload` при недоступных
кодеках:

- **Причина ошибки «scan failed — java.lang.NoClassDefFoundError:
  net/sourceforge/jaad/mp4/MP4Container».** Декодер `.m4a` (JAAD) живёт в
  jar-in-jar библиотеке `audio-codecs` внутри jar мода. Если она не загрузилась
  (неполный/перепакованный jar, конфликт с другим модом, причуды лаунчера),
  любой файл `.m4a/.aac/.mp4` в папке с музыкой убивал **весь** скан:
  `NoClassDefFoundError` — это `Error`, он обходил все пофайловые
  защиты, рвал нить скана — и вместе с ней весь reload.
- **Скан теперь не убить**: отсутствующий кодек или битый файл пропускает
  только этот один трек (с понятной причиной в чате и latest.log), остальные
  треки продолжают работать.
- **Диагностика кодеков**: в начале скана мод проверяет доступность всех
  четырёх кодеков (AAC/JAAD, MP3, Vorbis-декодер, Vorbis-энкодер) и пишет
  в latest.log ясный блок — что именно не загрузилось и что нужно
  переустановить полный jar мода.
- **Если у вас была эта ошибка**: удалите из mods **все** старые
  `custommusic-*.jar` и поставьте свежий jar 1.1.1 — доставляемый jar проверен
  на чистом сервере NeoForge 21.1.77 (m4a конвертируется за несколько секунд).
  Если кодеки в вашем окружении всё равно не видны — теперь мод прямо скажет
  об этом в чате и в логе, не уронив скан.

## Что нового в 1.1.0

1.0.2 → 1.1.0 — новый блок-проигрыватель **Juke Box**:

- **Блок «Juke Box»** (`custommusic:jukebox`) — крафтится из 8 дубовых досок и
  нотного блока, не двигается поршнями, ломается топором, при игре над ним
  парят нотки. Из выпадает сам блок при разрушении.
- **Меню по ПКМ** — список треков (двойной клик = играть), кнопка **Стоп**,
  переключатель **зацикливания** и два ползунка: **громкость** (10–100 %) и
  **дальность слышимости** (4–96 блоков).
- **Зацикливание** — клиентский звуковой экземпляр зацикливается безшовно
  (ванильный `LoopingAudioStream`), серверу это ничего не стоит; стоп по кнопке,
  по разрушению блока и при выгрузке чанка.
- **Громкость и дальность независимы друг от друга.** В ванилле громкость > 1
  лишь расширяет радиус слышимости (gain клампится в [0..1]), а радиус жёстко
  равен `max(volume,1) × attenuationDistance`. Мод заворачивает разрешённый
  звук в обёртку с `attenuationDistance = дальность` — затухание ровно до нуля
  на заданном расстоянии, а громкость задаёт чистый gain.
- **Сервер-авторитетно**: сервер знает состояние каждого Juke Box, рассылает его
  входящим в радиус игрокам (полусекундный sweep), сам останавливает
  незацикленные треки по точной длительности и раздаёт стоп при изменениях.
- Настройки и текущий трек сохраняются в NBT; после перезапуска мира
  воспроизведение возобновляется с начала трека, когда кто-то войдёт в радиус.

## Что нового в 1.0.2

1.0.1 → 1.0.2 — исправление «пластинка вставлена, но звука нет» и выравнивания
текста в меню выбора трека:

- **Воспроизведение в jukebox исправлено.** Клиентский виртуальный ресурспак
  генерировал `sounds.json` с ключами вида `custommusic:slot_7`, а ваниль
  строит id звукового события как `fromNamespaceAndPath(<namespace пака>,
  ключ)` — то есть ключи в `sounds.json` должны быть БЕЗ префикса (`slot_7`).
  Из-за лишнего префикса событие не находилось в SoundManager'е — пластинка
  вставалась, но играла в тишину. Теперь ключи правильные, трек играет.
- **Меню выбора трека.** Высота строки списка увеличена с 18 до 20 px — две
  строки текста (название + `id · длительность`) больше не упираются в нижнюю
  границу выделения и отцентрированы по вертикали.
- CI: шаг проверки папки `repo/` (из исправления сборки) печатает понятную
  ошибку, если кодеки не закоммичены.

## Что нового в 1.0.1

1.21.1 → 1.0.1 — это исправление «мод не видит треки»: в 1.0.0 конвертация
аудио была сломана в нескольких местах, из-за чего **ни один файл, кроме
моно-OGG, не попадал в список** (а на выделенном сервере мод ещё и не загружался
из-за конфликта пакетов кодеков). В 1.0.1:

- **`.m4a` / `.aac` / звуковые `.mp4`** — новая поддержка (декодер JAAD, public
  domain, работает даже с «moov в конце файла» — так сохраняют диктофон iPhone
  и многие загрузчики).
- **Кодирование в Ogg Vorbis работает**: встроенный чисто-Java энкодер
  `jVorbisEnc` (порт libvorbis) с исправленной таблицей данных. Раньше кодек
  vorbisspi не умел кодировать вовсе (только декодировать), и всё упиралось в
  внешний ffmpeg.
- **Парсер длительности OGG исправлен** (частота дискретизации читалась как
  ~0 — длительность превращалась в бесконечность).
- **`/customdisc reload` больше не фризит игру**: скан и конвертация идут в
  фоновом потоке, а перезагрузка датапаков выполняется **только если состав
  треков изменился**. Если ничего не поменялось — мод просто пишет «ничего не
  изменилось» без единого рывка.
- **Кодеки объединены в один jar** (`audio-codecs`): отдельные jar'ы vorbisspi и
  mp3spi содержат один и тот же пакет `javazoom.spi`, и модульная система Java
  отвергала их как split package — мод просто не загружался.
- **Отчёт по каждому файлу**: неподерживаемые форматы, превышение лимитов и
  ошибки декодирования видны прямо в чате после `/customdisc reload`.
- **Путь к папке печатается в чате** (`/customdisc list` при пустом списке и при
  каждом `/customdisc reload`) — сразу видно, куда именно мод смотрит.
- **Fallback на общую папку `.minecraft`**: если версия игры запущена из
  изолированной папки (`versions/<имя>/`), а треки лежат в общей
  `.minecraft/config/custommusic/music/` — мод найдёт их там (и напишет об этом
  в лог).

## Установка (важно: версия игры и NeoForge)

Моду нужен **Minecraft 1.21.1 + NeoForge 21.1.x** и **Java 21**. Он **не загрузится** в
сборках на других версиях — например, в модпаках на 1.12.2 (старый Forge не поймёт
`neoforge.mods.toml`, мод будет молча проигнорирован или уронит игру).

1. **Создай отдельную версию/инстанс** с Minecraft **1.21.1** и загрузчиком **NeoForge 21.1.x**
   (например, 21.1.77 или новее ветки 21.1):
   - **Официальный лаунчер / Prism / ATLauncher**: установи NeoForge 21.1.x через
     установщик с [neoforged.net](https://neoforged.net/) (или из списка версий лаунчера),
     выбери профиль в списке версий.
   - **TLauncher**: в поиске версий найди `1.21.1`, затем при создании версии выбери
     загрузчик **NeoForge 21.1.x**. Если для 1.21.1 NeoForge не предлагается — используй
     официальную связку выше (в TLauncher ветка NeoForge для новых версий бывает
     недоступна).
2. **Не смешивай моды разных версий игры.** У каждого инстанса должна быть своя папка
   `mods/`: старые моды 1.12.2 в папке `mods/` версии 1.21.1 будут генерировать ошибки
   загрузки, а наш мод в папке `mods/` версии 1.12.2 просто не заработает. В TLauncher
   по умолчанию все версии делят одну папку `.minecraft\mods\` — при проблемах задай
   инстансу отдельную папку игры (Настройки → Папка игры) или удали чужие моды из `mods/`.
3. Положи **`custommusic-1.1.1-all.jar`** в `mods/` выбранного инстанса 1.21.1 + NeoForge.
4. Убедись, что игра запускается на **Java 21** (в TLauncher это настройка Java-пути
   версии; JDK 21.0.11 из твоего лога подходит).
5. **Выделенный сервер**: поставь тот же jar в `mods/` сервера NeoForge 1.21.1,
   треки клади в `<сервер>/config/custommusic/music/`.

Проверка, что мод загрузился: в главном меню → Mods (Моды) → в списке есть
**Custom Music 1.1.1**; в игре работает `/customdisc list`.

## Как пользоваться

1. Установи мод (jar в `mods/`).
2. Положи свои треки в **`.minecraft/config/custommusic/music/`**
   (на выделенном сервере — в `config/custommusic/music/` **на сервере**).
   Поддерживаются `.ogg`, `.mp3`, `.wav`, `.m4a` (а также `.aac` и звуковые `.mp4`).
3. Зайди в мир и выполни `/customdisc reload`.
4. `/customdisc list` — посмотри список и `track_id` треков.
5. `/customdisc give <track_id> [player]` — получи пластинку.
6. Вставь пластинку в ванильный проигрыватель. Готово — трек играет
   **позиционно** (3D-затухание, как у ванильных пластинок), **синхронно для всех**
   игроков в радиусе слышимости и **сервер-авторитетно** (`SoundSource.RECORDS`).

### Блок Juke Box — с зацикливанием, громкостью и дальностью

Пластинки звучат как ваниль — 16 блоков и никакой настройки. Для «музыкального
центра» поставь **Juke Box**:

1. Скрафти: 8 дубовых досок + нотный блок (кольцо, нотный блок в центре)
   или возьми блок во вкладке «Инструменты и утилиты» креатива.
2. Поставь блок и щёлкни по нему **ПКМ** — откроется меню.
3. **Двойной клик** по треку в списке — играет. Играющий трек подсвечен золотом
   и помечен ♪, сверху строка «Играет: …».
4. **Зациклить: ВКЛ/ВЫКЛ** — трек повторяется безшовно, пока кто-нибудь не
   нажмёт «Стоп» (или блок не сломают).
5. **Громкость** (10–100 %) — чистый gain звука.
6. **Дальность** (4–96 блоков) — на каком расстоянии звук затухает до нуля.
   Внутри радиуса затухание плавное (чем дальше — тем тише), вне — тишина;
   вышел и вернулся — звук продолжается с того же места.
7. **Стоп** — остановить воспроизведение.

Меню закрывается само, если отойти дальше 16 блоков. Состояние (трек, зацикливание,
громкость, дальность) сохраняется в NBT — после перезапуска мира трек возобновится,
когда кто-то войдёт в радиус слышимости.

> 🔎 **Мод не видит треки?** Выполни `/customdisc list` — при пустом списке мод
> печатает **полный путь к папке, которую сканирует**. Сверь его с тем, куда ты
> положил файлы: лаунчеры (TLauncher и др.) могут запускать версию из
> **изолированной папки** `versions/<имя>/` — тогда «config» лежит в ней, а не в
> общей `.minecraft`. См. FAQ ниже.

### Геймплейный способ получения пластинок

Скрафти **чистую пластинку** (8 железных слитков + 1 редстоун, кольцо), щёлкни ею
ПКМ — откроется экран выбора трека. Выбери трек (двойной клик или «Записать») —
пластинка станет готовой к проигрыванию.

### Команды

| Команда | Права | Описание |
|---|---|---|
| `/customdisc list` | все | список треков: id, название, длительность |
| `/customdisc give <track_id> [player]` | OP 2 | выдать пластинку с треком |
| `/customdisc reload` | OP 2 | пересканировать папку и перезагрузить датапаки |

### Имена файлов → track_id

Имя файла превращается в безопасный идентификатор только из `[a-z0-9_.-]`
(маленькие буквы, цифры, `_ . -`). Кириллица транслитерируется, пробелы и скобки
становятся `_`, повторы `_` схлопываются:

| Файл | `track_id` |
|---|---|
| `Night Owl (Remix).ogg` | `night_owl_remix` |
| `Мой Крутой Трек.mp3` | `moy_krutoy_trek` |
| `Track-01 final (stereo).wav` | `track-01_final_stereo` |

Если два файла дают одинаковый id, второй получит суффикс `-2`.

## Как это работает (архитектура)

Ключевая проблема: `SoundEvent` нельзя зарегистрировать в рантайме (реестр
заморожен после старта), а нужно как-то связать произвольные файлы с
data-driven пластинками 1.21. Решение — **пул слотов + виртуальные паки**:

```
config/custommusic/music/*.ogg|mp3|wav
        │  сканер (TrackStore, сервер)
        ▼
конвертация в mono 44.1 kHz Ogg Vorbis  ──► config/custommusic/converted/<slug>.ogg
        │                                        (+ manifest.json, SHA-256)
        ├─► ВИРТУАЛЬНЫЙ ДАТАПАК (in-memory, AddPackFindersEvent, SERVER_DATA)
        │     data/custommusic/jukebox_song/<slug>.json
        │       { "sound_event": "custommusic:slot_<n>",
        │         "description": {"text": "<название>"},
        │         "length_in_seconds": <длина>, "comparator_output": 15 }
        │     data/minecraft/tags/item/music_discs.json → custommusic:music_disc
        │     ⇒ записи реестра jukebox_song грузятся штатным RegistryDataLoader
        │       и автоматически синхронизируются ванилью на клиенты
        ▼
   jukebox_song «slot_<n>»  ──►  ванильный JukeboxBlockEntity
        │  level.playSound(..., SoundSource.RECORDS, ...)
        ▼
   ClientboundSoundPacket("custommusic:slot_<n>")  ──► клиент
        │
        ├─► трек-лист + аудио передаются клиенту кастомными пакетами
        │   (чанки ~28 КБ, SHA-256, лимит chunksPerTick) в
        │   config/custommusic/client-cache/
        ▼
   ВИРТУАЛЬНЫЙ РЕСУРСПАК (in-memory, CLIENT_RESOURCES)
         assets/custommusic/sounds.json:
           "custommusic:slot_<n>": {"sounds": [{"name": "custommusic:tracks/<slug>",
                                                "stream": true}]}
         assets/custommusic/sounds/tracks/<slug>.ogg  ← из кеша
        ▼
   штатный SoundManager/SoundEngine → позиционное воспроизведение
```

Почему так:

- **Пул из 128 `SoundEvent`** (`custommusic:slot_0…slot_127`, `createVariableRangeEvent`)
  регистрируется через `DeferredRegister` до старта игры; каждый трек детерминированно
  (стабильный хеш slug + линейное пробирование) получает свой слот. Идентичность
  трека передаётся через id звука — поэтому **не нужны** ни подмена аудиопотока на
  лету, ни миксины в звуковой движок.
- **Виртуальный датапак** (`AddPackFindersEvent`, `PackType.SERVER_DATA`) генерирует
  `jukebox_song/*.json` и тег `music_discs` — записи реестра создаются **штатным**
  `RegistryDataLoader` (миксин в него не понадобился) и штатно же синхронизируются
  ванилью на клиенты (это синхронизируемый датапак-реестр в 1.20.5+).
- **Виртуальный ресурспак** на клиенте генерирует `sounds.json` и отдаёт аудио из
  кеша — весь проигрыванием занимается ванильный звуковой движок (стриминг,
  громкость Records, 3D-затухание).
- Предмет — один `custommusic:music_disc`, конкретный трек хранится в компоненте
  `minecraft:jukebox_playable` (как у ванильных пластинок): тултип с названием,
  таймер песни, авто-выброс, компаратор — всё работает ванильно.
- Единственный миксин — диагностический (`SoundEngineMixin`, клиент): печатает
  внятное предупреждение, если слот ещё не скачан клиентом.

### Форматы, конвертация и этапы

Ванильный звуковой движок играет только **Ogg Vorbis**, а 3D-затухание работает
только для **моно** (стерео в OpenAL не позиционируется). Поэтому всё конвертируется
в **mono 44.1 kHz Ogg Vorbis** на сервере — **встроенными чисто-Java кодеками,
без внешних программ**:

| Вход | Что происходит |
|---|---|
| `.ogg` mono 44.1 kHz | passthrough — файл копируется без перекодирования |
| `.ogg` стерео/другой частоты | декод (vorbisspi) → downmix в моно → ресемплинг → Ogg (jVorbisEnc) |
| `.mp3` | декод (mp3spi) → downmix → ресемплинг → Ogg |
| `.wav` | декод (JavaSound) → downmix → ресемплинг → Ogg |
| `.m4a` / звуковой `.mp4` | декод (JAAD, AAC-LC/HE-AAC, в т.ч. «moov в конце») → downmix → ресемплинг → Ogg |
| `.aac` (ADTS) | декод (JAAD) → downmix → ресемплинг → Ogg |

Кодирование в Ogg Vorbis выполняет **jVorbisEnc** (чисто-Java порт libvorbis) —
с исправленной таблицей данных: в апстриме опечатка «-7 - 3» вместо «-7, -3»
в `_vp_tonemask_adj_longblock` ломала инициализацию кодека. Кодеки декодирования
собраны в **один jar** (`audio-codecs`): отдельные jar'ы vorbisspi и mp3spi
конфликтуют одинаковым пакетом `javazoom.spi`, и модульная система Java (split
packages) не даёт им загрузиться вместе.

Фолбэк: если встроенные кодеки не справились (например, ALAC/DRM внутри `.m4a`) —
внешний `ffmpeg` (`ffmpeg -ac 1 -ar 44100 -c:a libvorbis`), путь настраивается
в конфиге (`ffmpegPath`, пусто = выключить).

Перекодирование выполняется один раз (при `/customdisc reload` — в фоновом
потоке, без фриза) и кешируется по SHA-256 исходника (при изменении файла —
перекодируется, без изменения — переиспользуется). Недекодируемый файл —
**предупреждение в лог + причина прямо в чате**, игра не падает.

### Лимиты (конфиг `config/custommusic-common.toml`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `maxTracks` | 128 | максимум треков (= размер пула слотов) |
| `maxFileSizeMb` | 50 | максимальный размер одного файла |
| `maxDurationSeconds` | 600 | максимальная длительность трека |
| `allowUnconvertibleStereo` | false | оставить стерео без 3D-затухания, если нельзя сконвертировать |
| `ffmpegPath` | `ffmpeg` | путь к ffmpeg (пусто = отключить фолбэк) |
| `chunksPerTick` | 8 | скорость синхронизации аудио (чанков ~28 КБ за тик) |

## Сборка

Нужен любой JDK 21. Gradle-обёртка уже включена в проект:

```bash
./gradlew build  # Windows: gradlew.bat build
```

> ⚠️ **Только Gradle 8.x, не 9.x.** Плагин сборки NeoGradle 7.0.x несовместим с
> Gradle 9: там удалён внутренний метод `GUtil#toCamelCase`, и любая команда
> (включая `gradle wrapper`) падает на конфигурации с ошибкой
> `'java.lang.String org.gradle.util.internal.GUtil.toCamelCase(...)'`.
> Обёртка `gradlew` закреплена на **8.10** — всегда собирайте через неё.
> Если обёртку нужно сгенерировать заново, делайте это Gradle 8.x:
> `gradle wrapper --gradle-version 8.10` (не `gradle wrapper` без версии).

Готовый jar: **`build/libs/custommusic-1.1.1-all.jar`** (задача `jarJar` кладёт
аудиокодеки внутрь jar — именно этот файл ставьте в `mods/`). Рядом собирается
`custommusic-1.1.1.jar` без кодеков (работает только с mono `.ogg`).
CI в комплекте (`.github/workflows/build.yml`) — GitHub Actions сам соберёт jar
и приложит его к рану (Artifacts).

> ⚠️ **Папка `repo/` обязана быть закоммичена в git целиком** — вместе с jar'ами,
> `.pom` и **`maven-metadata.xml`**. В `build.gradle` кодеки разыменовываются
> версионными диапазонами `[1.0,)` / `[0.0.3,)`, а Gradle перечисляет версии
> maven-репозитория **только по `maven-metadata.xml`** — директории он не листает.
> Если `repo/` не запушен или в нём нет метаданных, сборка падает с
> `Could not find any matches for dev.custommusic:audio-codecs:[1.0,)`.
> CI перед сборкой проверяет все шесть файлов и подсказывает решение:
> `git add -A repo/ && git commit -m "ci: add bundled codec repository" && git push`
> (если jar'ы игнорируются глобальным `.gitignore` — `git add -f repo/`).

> **Совет по JDK:** первая сборка запускает пайплайн NeoForm (декомпиляция и
> патчинг Minecraft). Для воспроизводимого результата рекомендуется JDK 21.0.3
> или 21.0.4 (эпоха 1.21.1) и ~4 ГБ свободной памяти — подробности в
> [DEVNOTES.md](DEVNOTES.md).

Быстрый запуск для разработки: `./gradlew runClient` / `./gradlew runServer`.

Подробности о чувствительных к версиям API — в [DEVNOTES.md](DEVNOTES.md).

> 🛠 **Сборка в ограниченном окружении**: если NeoForm-декомпиляция не
> укладывается в лимиты (4 ГБ ОЗУ / окно сборки), можно скомпилировать мод
> javac'ом против артефактов, которые пайплайн успел создать: скрипты
> `patch_access.ts` → `compile_sandbox.sh` → `package_sandbox.sh` (подробности в
> [DEVNOTES.md](DEVNOTES.md)). Каноническая сборка — по-прежнему `./gradlew build`.

## Ограничения и FAQ

- **«Мод не видит мои треки!» — №1 причина: не та папка.** Выполни
  `/customdisc list` (при пустом списке) или `/customdisc reload` — мод печатает
  **полный путь к папке, которую сканирует**. Проверь, что файлы лежат именно
  там. Лаунчеры (TLauncher и др.) позволяют запускать версию из изолированной
  папки `versions/<имя>/` — тогда мод ищет треки в `versions/<имя>/config/custommusic/music/`,
  а не в общей `.minecraft/config/custommusic/music/`. Обратная ситуация тоже
  возможна: если общая папка `.minecraft/config/custommusic/music/` содержит
  треки, а изолированная пуста — мод сам найдёт общую и напишет об этом в лог.
- **«После reload игра фризит»** — начиная с 1.0.1 скан и конвертация идут в фоновом
  потоке, а перезагрузка датапаков выполняется только если состав треков
  изменился (об этом пишет в чате). Короткий рывок возможен только в момент
  реальной перезагрузки датапаков при изменении треков — как у ванильного /reload.
- **Почему трек конвертируется в моно?** Стерео-источники в OpenAL не имеют
  3D-затухания — трек звучал бы «на всю карту». Моно даёт честное позиционное
  затухание, как у ванильных пластинок. Если стерео критично, а кодеков нет —
  см. `allowUnconvertibleStereo`.
- **Выделенный сервер:** клиенту с модом треки скачиваются автоматически при
  входе (~секунды на альбом). Пока синхронизация не закончилась, пластинка
  вставится, но будет молчать — всё доиграется после F3+T/автоперезагрузки.
- **Больше 128 треков?** Лишние пропускаются с предупреждением (пул слотов
  фиксирован на этапе регистрации реестра — это цена решения без миксинов).
- **Удалил трек из папки?** После `/customdisc reload` запись исчезнет из
  реестра; старые пластинки просто перестанут играть (без крашей).
- **F3+T во время песни** перезапускает звуковой движок — звук прекратится,
  но «проигрывание» пластинки продолжится ванильно до конца таймера.
- **Мод на клиенте обязателен?** Да: сервер раздаёт данные, а играет их
  клиентский звуковой движок через виртуальный ресурспак.

## Лицензии зависимостей

Код мода — MIT. Внутрь jar (jar-in-jar) кладутся два артефакта из локального
репозитория `repo/` (см. `repo/dev/custommusic/…/*.pom` с описанием):

- **`audio-codecs-1.0.jar`** — слитые декодеры JavaSound: `jlayer`, `jorbis`,
  `tritonus-share`, `vorbisspi`, `mp3spi` (LGPL, com.googlecode.soundlibs) +
  `jaad` (public domain, AAC/`.m4a`/`.aac`/`.mp4`). Слиты в один jar, т.к.
  отдельные vorbisspi и mp3spi конфликтуют пакетом `javazoom.spi` (split
  package в модульной системе Java).
- **`jvorbisenc-patched-0.0.3.jar`** — чисто-Java кодировщик Ogg Vorbis
  (порт libvorbis; апстрим [jVorbisEnc](https://github.com/umjammer/jVorbisEnc),
  стиль BSD от Xiph.Org) с исправленной таблицей данных (опечатка в
  `_vp_tonemask_adj_longblock`).
